How a governed agent works

Five steps are automatic. The sixth always belongs to a person.

  1. 01

    Trigger

    A schedule or an event starts it. Nobody has to remember.

  2. 02

    Context

    It reads your facts, your rules and its notes from earlier runs before it acts.

  3. 03

    Tools

    Read-only access to named systems, through one gate. Nothing else.

  4. 04

    Judgment

    It compares with history and with thresholds you write in plain words.

  5. 05

    Evidence

    A report where every number cites its source, or says "not reached".

  6. 06

    A person decides

    People read the actions and apply the changes. The agent cannot.

Five principles you can check

Reads widely, writes narrowly

An agent reads the systems it is asked about and writes only where its reports and proposals are kept. It holds no credential that could change a server, a firewall rule or a document.

Never sees a secret

Credentials are swapped into requests at the network edge, only for the one host each belongs to. Inside the agent's workspace they are placeholders; leaking one leaks nothing.

Evidence or silence

Every figure names the query and time range behind it. When a source cannot be reached, the report says so and leaves the number empty. It never estimates.

Private by construction

Reports carry aggregates only. A built-in gate refuses to publish anything containing an outside email address, an IP address or a stranger's domain.

Bounded in every direction

It reaches the few hosts it needs and nothing else on the internet. Its instructions change only through a reviewed repository, never through the agent itself. Everything it reads is treated as data, never as instructions.

Questions a client asks

The honest answers.

Can it change anything in our systems?

No. The identity it signs in with can only read: Reader on Azure and read-only permissions on Microsoft 365, GitHub and Cloudflare. The only thing it writes is the record, into a repository you own.

Where does our data go?

Into your own private repository, in your own GitHub organization, under an identity your admin grants. Nothing is copied to VZOR's systems. VZOR's practitioners read it with access you grant for the engagement and remove when it ends.

Does an AI read our configuration?

Not in the evidence pack. The collector and the renderers are plain code. VZOR runs an AI agent on its own evidence, as a demonstration and to keep its own handbook true; it never reads a client's record. If that ever changes, it will be by a written agreement, not by default.

Does this certify us?

No. Certification is the certification body's decision. The system prepares you for it: dated, repeatable, signed evidence, and a clear list of what a person still has to keep.
